# GitHub Copilot Feature Review Checklist — Leave Management Demo

Use this guide to review Copilot capabilities against one small, browser-only app.

## Core demo (25–30 minutes)

| # | Feature | Demo action | Evidence to show |
|---|---|---|---|
| 1 | Code Chat | Ask Copilot to explain `app.js` without edits | Explanation grounded in existing functions |
| 2 | Inline code completion | Start a helper function and accept/reject a suggestion | Suggested code appears as you type |
| 3 | Inline Chat / Edit | Select validation logic and request a focused improvement | Review proposed diff before accepting |
| 4 | Plan mode | Ask for a plan to add leave-day calculation; request no edits | Ordered plan and files involved |
| 5 | Agent mode | Ask it to implement leave-day calculation across HTML/CSS/JS | Multi-file changes and reasoning |
| 6 | Bug fixing | Test end date earlier than start date, ask Copilot to find cause | Root cause, suggested fix, test cases |
| 7 | Test generation | Ask for edge-case test cases and a simple testing approach | Test plan and any generated tests |
| 8 | Code review | Ask it to inspect the current diff for logic/accessibility/security | Findings with severity and rationale |
| 9 | Documentation | Ask for README and a summary of changes | Useful setup notes and known limitations |
| 10 | Commit message | Ask for a concise commit message based on actual changes | Message that matches the diff |

## GitHub workflow demo (10–15 minutes)

1. Create a GitHub repository and upload the demo files.
2. Create a branch named `feature/leave-day-validation`.
3. Make one small change using Copilot.
4. Commit and push the branch.
5. Open a pull request against the default branch.
6. Request a Copilot review if the feature is available in your account and enabled by your organisation.
7. Read review comments, verify whether they are valid, and apply only appropriate changes.
8. Ask Copilot to draft a pull request summary and test checklist.

## Suggested prompts

### Code Chat
> Explain how the leave request form works. Describe the role of index.html, style.css and app.js. Identify validation gaps. Do not edit files.

### Inline edit
> Reject an end date earlier than the start date and trim the employee name. Keep the existing app dependency-free. Make the smallest change possible and explain it.

### Plan
> Plan how to add leave-day calculation, leave balance validation and a pending-request summary. List the files to change and test cases. Do not implement yet.

### Agent
> Implement leave-day calculation in the request list. Update the existing HTML/CSS/JavaScript only where necessary. Handle invalid dates, add clear user feedback, and do not add dependencies or a backend. Summarise the files changed.

### Bug fix
> Find the cause of this app accepting an end date before the start date. Explain the root cause and propose the smallest fix. Include valid and invalid test cases.

### Code review
> Review my current diff for logic bugs, date calculation errors, accessibility, unsafe DOM manipulation and maintainability. Rank findings by severity and cite the relevant lines or functions. Do not edit files.

### Test generation
> Propose tests for same-day leave, multi-day leave, an end date before the start date, missing dates, invalid dates, and a blank employee name. This is a browser-only app; recommend a simple test setup and identify what needs to be installed, if anything.

### Custom instructions
Create `.github/copilot-instructions.md` with:
> Keep this app plain HTML, CSS and JavaScript. Do not add a framework, package or backend. Validate date ranges, trim text inputs, use accessible labels and status messages, avoid unsafe DOM insertion of user input, and explain changes before editing unrelated files.

### Documentation
> Draft a README describing the app, features, how to open it, its limitations and the changes in this branch. Do not claim the app has a backend, persistent storage, or automated tests unless those are actually implemented.

## What this demo can and cannot prove

- This front-end app can demonstrate code chat, suggestions, editing, agent workflows, code review prompts, documentation, and GitHub pull-request review.
- Automated test execution requires a test setup and whatever runtime it uses. A test plan generated by Copilot is not the same as tests being executed.
- Pull-request review requires the files to be in a GitHub repository and the feature to be available/enabled.
- The app stores sample requests only in page memory. Refreshing loses them. Do not use real employee data.
- Copilot output is not automatically correct. Verify every change and test the app.

## Suggested presentation timing

- 0–3 min: Introduce the app and its current limitations.
- 3–6 min: Code Chat and inline completion.
- 6–12 min: Inline edit and plan mode.
- 12–18 min: Agent mode implements a small feature.
- 18–22 min: Bug fixing and test generation.
- 22–27 min: Code review and documentation.
- 27–35 min: Pull request workflow, if enabled.
